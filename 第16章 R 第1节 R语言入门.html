第16章 R 第1节 R语言入门

前言

R语言，作为一门为统计计算与图形显示而生的开源编程语言，早已经成为学术界和工业界进行数据分析的黄金标准。它不仅拥有无与伦比的统计分析能力、顶尖的可视化引擎，更重要的是，它背后有一个活跃的、由全球顶尖统计学家和数据科学家组成的社区，持续不断地贡献着最前沿的分析方法和工具包。

本章，我将为读者提供一份内容全面的R语言快速入门指导。我们将以R的基础（Base R）功能为主线，这是理解R运行机制的根基；同时，我们也会适时引入ggplot2、dplyr等在特定领域表现卓越的工具包，以展示R生态系统的强大与便捷。

我们将严格按照统计学学习的逻辑脉络展开，从最基础的数据描述，到经典的统计推断，再到应用广泛的回归模型，最后延伸至当前热门的机器学习算法。

一、R语言的独特优势

在Python主导AI开发的时代，R语言依然在量化金融、生物统计和学术研究领域占据不可替代的生态位。这种生命力源于其深厚的设计哲学和独特的工具链。

优秀的统计基因。R诞生于1992年，由新西兰奥克兰大学的Ross Ihaka和Robert Gentleman为统计计算而开发。这种出身决定了R在时间序列分析、回归诊断、假设检验等统计核心场景中的天然优势——语法直接、函数完备。R的时间序列分析包如forecast、xts、zoo等提供了ARIMA、GARCH等经典模型的完整实现。

完善的包生态。CRAN（Comprehensive R Archive Network）上拥有超过18,000个扩展包，覆盖从数据导入到高级建模的全链路。金融领域有quantmod用于数据抓取与可视化、PerformanceAnalytics用于风险指标计算、rugarch用于GARCH建模。tidyquant包更是将量化金融分析无缝整合进了tidyverse生态。

一流的数据探索体验。RStudio（现Posit）提供了业界领先的集成开发环境，四大面板（源代码编辑器、环境/历史查看器、控制台、文件/图形/包/帮助）让数据探索的每一次迭代都极为流畅。快速原型验证的速度，是R在学术研究和策略开发中备受青睐的重要原因。

可复现报告。配合R Markdown或Quarto，可以一键生成融合代码、图表和文字的研究备忘录。这种“文学化编程”的工作流极大便利了投委会审查、学术评审和团队协作。

二、环境搭建

1. 安装R和RStudio

第一步：安装R

R是核心的解释器和计算引擎。

访问CRAN官网（https://cran.r-project.org/），选择对应操作系统（Windows/macOS/Linux）的安装包下载并运行，按提示完成安装。

第二步：安装RStudio

RStudio是一个强大且极受欢迎的R语言集成开发环境（IDE）。它提供了代码编辑器、控制台、环境/历史记录查看器、文件/图表/包管理器等多种功能于一体的友好界面，极大地提升了R语言的使用体验。

访问Posit官网（https://posit.co/download/rstudio-desktop/），下载免费的RStudio Desktop版本并安装。务必先安装R，再安装RStudio。安装完成后，直接打开RStudio（而非R本身）。

RStudio的核心界面包含四个面板：

  • 源代码编辑器：编写和保存R脚本
  • 控制台：直接执行R命令
  • 环境/历史：查看已创建的变量对象
  • 文件/图形/包/帮助：管理文件、查看绘图、安装包、查阅文档

务必理解R和RStudio的关系，R是解释器和计算引擎，RStudio是集成开发环境。先安装R，再安装RStudio。

2. 包的安装与加载

R包可以通过两种方式安装：

# 从CRAN安装单个包
install.packages("dplyr")


# 一次性安装多个包
install.packages(c("ggplot2", "tidyr", "readr"))


# 安装tidyverse全家桶
install.packages("tidyverse")

加载包使用library()函数：

library(dplyr)
library(ggplot2)

最佳实践：在脚本开头集中加载所有需要的包，便于他人了解依赖关系。若需查看已安装的包列表，使用installed.packages()；查看当前已加载的包，使用search()。

三、基础数据类型

R语言中，所有对象最终都可以拆解为以下五种基本类型。

1. 五大数据类型

1.1 逻辑型（Logical）

取值仅为 TRUE 和 FALSE（可简写为 T 和 F，但强烈建议写全称以避免意外覆盖）。

logical_vec <- c(TRUE, FALSE, TRUE)
typeof(logical_vec)  # "logical"

关键特性：在算术运算中，TRUE 自动强制转换为 1，FALSE 转换为 0。

sum(c(TRUE, FALSE, TRUE))  # 结果为 2

1.2 整数型（Integer）

用于存储整数。声明时必须在数字后加 L 后缀，否则R默认创建双精度浮点型（double）。

int_vec <- c(1L, 2L, 3L)
typeof(int_vec)  # "integer"


# 不加L则为double
typeof(c(1, 2, 3))  # "double"

注意：length() 和索引操作返回的值往往是 integer 类型。实际应用中，分类变量的ID编码建议显式声明为 integer 以节省内存。

1.3 双精度浮点型（Double / Numeric）

这是R中数值型的默认存储方式，涵盖整数、小数和科学计数法表示的数。R文档中常将 double 统称为 numeric。在 is.numeric() 检查时，integer 和 double 都会返回 TRUE，但 typeof() 会严格区分。

num1 <- 3.14
num2 <- 2e-3  # 0.002
typeof(num1)  # "double"

注意：若未加 L 后缀，c(1, 2, 3) 的类型是 double 而非 integer，这在内存敏感的大数据处理时需留意。

1.4 字符型（Character）

存储文本字符串。R内部使用全局字符串池（global string pool）来优化内存，但在向量化操作中仍比数值型计算耗资源。

char_vec <- c("apple", "banana", "cherry")
typeof(char_vec)  # "character"

1.5 复数型（Complex）

存储复数，格式为 a + bi。主要用于工程数学和信号处理，在常规金融数据分析中极少使用。

comp <- 1 + 2i
typeof(comp)  # "complex"

2. 数据类型检查与判断

在R中，注意区分“类型”与“类”。类型（typeof）是R底层的C语言级定义，类（class）是面向对象系统赋予的属性（如 Date、factor、data.frame）。

检查时请遵循以下最佳实践：

检查场景 推荐函数 说明
底层存储类型 typeof(x) 返回 "double"、"integer" 等
面向对象类 class(x) 返回 "data.frame"、"Date"、"factor" 等
是否为数值（含整数） is.numeric(x) 对 integer 和 double 都返回 TRUE
是否为纯浮点数 is.double(x) 严格区分 integer 和 double
是否为单个 TRUE/FALSE is.logical(x) 向量元素检查需配合 any() 或 all() 
x <- 1L
typeof(x)      # "integer"
class(x)       # "integer"
is.numeric(x)  # TRUE


y <- as.Date("2026-09-02")
typeof(y)      # "double"（日期底层本质是双精度数值）
class(y)       # "Date"

3. 类型强制转换（Coercion）

R是动态类型语言，但底层是强类型的。当五种数据类型在向量中混合时，R会依据 向上兼容 的规则自动强制转换：character > double > integer > logical。

mixed <- c(TRUE, 1L, 3.14, "text")
typeof(mixed)  # "character"（字符型层级最高，所有元素被转为字符）

手动强制转换是生产环境中必须掌握的技能：

as.numeric("3.14")    # 3.14
as.integer(3.99)      # 3（直接截断，四舍五入需用 round()）
as.character(100)     # "100"
as.logical(1)         # TRUE
as.logical(0)         # FALSE

风险提示：非数值字符转数值会返回 NA 并产生警告。

as.numeric("hello")   # NA with warning

4. 特殊值（Special Values）

R中的缺失、未定义和无穷大有着严格的类型归属：

  • NA（缺失值）：具有类型属性。R提供了 NA_integer_、NA_real_、NA_character_ 和 NA_logical_。使用 c() 合并时，NA 会被自动强制转换为向量中其他元素的类型。

    c(1, NA)      # NA 变成 NA_real_
c("a", NA)    # NA 变成 NA_character_

    检查缺失值必须使用 is.na()，切忌使用 == NA。

  • NULL（空对象）：表示“没有值”或“无对象”。注意 NULL 与 NA 的区别——NULL 没有类型，长度为0；NA 长度为1且有类型。

  • Inf 与 -Inf（正负无穷）：属于 double 类型，通常由除以0产生。

    1 / 0          # Inf
is.infinite(1 / 0)  # TRUE

  • NaN（非数值）：属于 double 类型，由无效的数学运算产生（如 0 / 0）。NaN 也属于 is.na() 的捕捉范围，但 is.nan() 可严格区分。

5. R 中没有“标量”

在R语言中，不存在独立的标量数据类型。所谓的“单个数字”或“单个字符串”，本质上是长度为1的原子向量。

scalar <- 3.14
length(scalar)   # 1
is.vector(scalar) # TRUE

这意味着R中的所有原子数据都以向量为基本单位，这也是R原生支持向量化运算的根本原因。理解这一点，就能自然接受为什么 if (condition) {} 中的 condition 必须是一个长度为1的逻辑值（若长度为大于1的向量，仅取第一个元素并给出警告）。

四、基础数据结构

R中存储的一切数据都称为对象（object）。理解R的核心数据结构，是掌握这门语言的关键。

1. 向量（Vector）

向量是R最基础的数据结构，是一个一维的有序元素序列。向量中的元素类型必须相同（数值型、字符型、逻辑型等）。

# 使用c()函数创建向量
numeric_vec <- c(1, 2, 3, 4, 5)
char_vec <- c("apple", "banana", "cherry")
logical_vec <- c(TRUE, FALSE, TRUE)


# 查看向量类型
typeof(numeric_vec)  # "double"

若向量中混合了不同类型，R会自动进行强制类型转换，层级规则为：character > numeric > logical。

mixed <- c(1, "two", TRUE)
# 全部被转换为字符型："1", "two", "TRUE"

2. 数据框（Data Frame）

数据框是R中最常用的数据结构，类似于电子表格或数据库表——由行和列组成，每列可以存储不同类型的数据（数值、字符、因子等）。

# 创建数据框
df <- data.frame(
  name = c("Alice", "Bob", "Charlie"),
  age = c(25, 30, 35),
  salary = c(50000, 60000, 70000)
)


# 查看数据框结构
str(df)
# 预览前几行
head(df)

默认情况下，data.frame()会将字符型列自动转换为因子（factor）。若希望保留字符型，可设置stringsAsFactors = FALSE。

3. 矩阵（Matrix）

矩阵是二维数据结构，所有元素必须为同一原子类型（数值、字符、逻辑等），本质上是带有维度（dim）属性的向量。矩阵专用于数值计算、线性代数运算和距离度量等场景，与数据框（允许各列不同类型）形成互补。

创建矩阵：使用 matrix() 函数，默认按列填充（byrow = FALSE）。

# 按列填充 3行2列
mat <- matrix(1:6, nrow = 3, ncol = 2)
#      [,1] [,2]
# [1,]    1    4
# [2,]    2    5
# [3,]    3    6


# 按行填充
mat_row <- matrix(1:6, nrow = 3, ncol = 2, byrow = TRUE)

属性与命名：可通过 dim() 查看维度，rownames() 和 colnames() 设置行列名。

dim(mat)          # 3 2
colnames(mat) <- c("A", "B")
rownames(mat) <- c("r1", "r2", "r3")

矩阵与数据框的区别：

特性 矩阵 数据框
元素类型 单一类型 每列可不同
用途 数学运算、线性代数 混合数据存储、统计分析
索引降维 默认 drop = TRUE 默认 drop = TRUE（但列子集行为因语法而异）
转置/乘法 支持 t(), %*% 不支持直接线性代数

常见操作：矩阵转置（t()）、矩阵乘法（%*%）、行列求和（rowSums()、colSums()）、apply族函数（apply(mat, 1, mean) 按行计算均值）。在金融中，协方差矩阵、相关性矩阵、投资组合权重向量等均以矩阵形式存储与运算，是量化分析的基础容器。

4. 列表（List）

列表是R中最灵活的数据结构，可以容纳任意类型的对象——向量、矩阵、数据框，甚至其他列表。

# 创建列表
my_list <- list(
  numbers = c(1, 2, 3),
  name = "Alice",
  is_active = TRUE,
  nested = list(a = 1, b = 2)
)


# 访问列表元素：三种方式
my_list$name              # "Alice"
my_list[["numbers"]]      # 返回向量
my_list["numbers"]        # 返回列表（子集）

注意[与[[的区别：[返回的是列表（子集），[[返回的是元素本身。

5. 因子（Factor）

因子用于表示分类变量，是带有层级（levels）的字符串向量。

# 创建因子
gender <- factor(c("male", "female", "male", "female"))
levels(gender)  # "female" "male"


# 有序因子
rating <- factor(c("low", "high", "medium"),
                 levels = c("low", "medium", "high"),
                 ordered = TRUE)

因子在统计建模（如线性回归中的分类变量编码）和可视化（如ggplot2的分组着色）中至关重要。

6. 时间序列（Time Series）

R在时间序列分析领域具有深厚的积累。Base R提供了ts()函数用于创建规则的时间序列对象：

# 创建月度时间序列（2015年1月起，12个月）
ts_data <- ts(1:12, start = c(2015, 1), frequency = 12)

金融时间序列分析中，更常用的是xts（eXtensible Time Series）和zoo包，它们支持不规则时间序列和更丰富的时间索引操作。Rmetrics套件中的timeSeries包则基于S4类系统，提供了专为金融数据设计的时间序列对象。

五、索引与子集机制

在R的数据操作中，索引（Subsetting）是最高频的操作。熟练区分 [、[[、$ 的语义，理解底层的内存与匹配机制，是从“写R脚本”进阶到“构建稳健R系统”的分水岭。

1.三大操作符

这是R索引中最关键的概念区分，绝不可混用：

操作符 名称 返回类型 适用场景
[ 子集提取 保持原对象的类（容器） 取数据框的多列、向量的多个元素
[[ 元素提取 去掉容器，返回内部元素本身 从列表/数据框中取出具体向量/对象
$ 按名访问 同 [[（语法糖） 按名称取列表/数据框的单个列，支持部分匹配 
lst <- list(a = 1:5, b = "text", c = data.frame(x = 1:3))


# [ ] 返回列表（容器）
lst[1]       # 返回列表，长度1，内部是向量
class(lst[1]) # "list"


# [[ ]] 返回向量本身
lst[[1]]      # 返回整数向量 1:5
class(lst[[1]]) # "integer"


# $ 语法糖
lst$a         # 等价于 lst[["a"]]

2.四种索引方式

R允许使用以下四种形式来指定位置，它们适用于向量、列表和数据框的行/列。

2.1. 正整数索引：按位置取。

```r
vec <- c(10, 20, 30, 40)
vec[c(1, 3)]  # 10 30
```

####2.2. 负整数索引：排除指定位置（不能与正整数混合使用）。 r vec[-2] # 10 30 40（排除第2个） vec[-c(1,4)] # 20 30 # 注意：vec[c(1, -2)] 会报错，正负不可混用

####2.3. 逻辑索引：最强大的过滤方式，向量长度为TRUE的位置被保留。处理NA时要格外小心。 r vec[vec > 20] # 30 40 # 若存在缺失值：vec <- c(10, NA, 30); vec[vec > 20] 返回 NA 30 # 若要去除NA，需显式加上：vec[!is.na(vec) & vec > 20]

####2.4. 字符索引：基于命名向量（names attribute）或数据框列名。 r named_vec <- c(a = 1, b = 2, c = 3) named_vec[c("a", "c")] # 1 3

3.按数据结构特化

不同的数据结构对索引的响应细节差异极大，这是R初学者最容易犯错的地方。

3.1. 向量（Vector）

一维，取出的仍是向量。若使用 [[，依旧取出元素（原子向量长度为1时取出标量）。

3.2. 列表（List）

  • list[1] 永远返回列表。
  • list[[1]] 返回该位置对象的原始类型（如数据框、函数或向量）。
  • 若列表嵌套，需连续使用 [[：lst[[1]][[2]]。

3.3. 数据框（Data Frame）

数据框本质是列等长的列表。索引分为行与列两个维度 df[行, 列]。 关键机制：drop 参数。这是导致R代码行为意外的主要原因。

  • df[ , "col_name"] —— 默认 drop = TRUE，返回向量（降维）。
  • df[ , "col_name", drop = FALSE] —— 返回单列数据框。
  • df["col_name"] —— 不指定行，只传入列标签，默认 drop = FALSE，返回数据框（因为未触发二维切片）。
df <- data.frame(id = 1:3, value = c(4, 5, 6))


str(df[, "value"])        #  int [1:3]（向量）
str(df[, "value", drop = FALSE]) # 'data.frame': 3 obs. of 1 variable（数据框）
str(df["value"])          # 数据框（保险行为）

生产环境最佳实践：编写自定义函数时，若不确定返回值是否需要向量，一律使用 drop = FALSE 以避免数据框意外退化为向量导致下游管道报错。

3.4. 矩阵（Matrix）

二维，mat[1, ] 默认 drop = TRUE 返回向量，mat[1, , drop = FALSE] 返回行矩阵。

4.深层机制：内存、匹配与性能

4.1. 写时复制（Copy-on-Modify）与内存行为

Base R 中，[ 和 [[ 索引操作默认返回物理副本（deep copy），而非引用。这意味着：大型金融时间序列（如高频tick数据）若频繁切片，会产生大量内存复制，拖慢GC（垃圾回收）。处理海量数据时，优先使用 data.table 包（其 DT[1:5] 默认不复制，除非赋值）或使用 R6 引用类。

4.2. 部分匹配（Partial Matching）机制

  • $ 默认允许部分匹配。若数据框有列 summaries，调用 df$sum 会返回 summaries 列，不会报错。
  • [[ 可设置 exact = FALSE 开启部分匹配，默认为 TRUE（严格匹配）。
  • [ 字符索引不允许部分匹配，必须完全一致。

4.3. 逻辑索引与 which() 的性能抉择

  • 直接逻辑向量：df[df$col > 0, ]。速度最快，但若逻辑向量含 NA，返回的行中对应位置全为 NA（脏数据）。
  • which() 包裹：df[which(df$col > 0), ]。会忽略 NA，返回干净子集，但多了一次函数调用开销（在百万级数据下差异极小，建议在含NA的场景下使用 which）。
  • subset() 函数：subset(df, col > 0) 自动忽略 NA，但用于编程环境时注意其非标准计算可能引发R CMD check警告，适合交互式分析。

4.4. 区间与空索引的特殊语义

  • 空索引：df[] 返回数据框本身，常用于重置内部引用或规避 drop 属性。
  • 按位置区间：df[1:5, ] 取前五行，但注意 1:5 生成的是整数向量，若 nrow(df) < 5，不会报错，只取存在的行（静默截断），这在循环中可能产生意外空数据框，建议前置 seq_len(nrow(df)) 控制边界。
场景 推荐写法 原因
取数据框单列用于计算 df[["col"]] 或 df[, "col", drop = TRUE] 返回向量，保证计算效率
取数据框单列作为子集传入函数 df["col"] 或 df[, "col", drop = FALSE] 保持数据框结构，避免泛型函数分派异常
按条件过滤含NA的数据 df[which(df$col > 0), ] 或 subset(df, col > 0) 剔除缺失干扰，保持结果行数干净
循环中动态构建列名 df[[paste0("var", i)]] [[ 支持变量传递，$ 不支持
编写生产级R包 避免使用 $，全部替换为 [[ 或 [, ] 杜绝部分匹配，确保代码健壮性

5. 从”1”开始索引

R语言从1开始索引。这根植于其统计计算基因。数学中的向量、矩阵下标天然从1起，这与统计学家和量化研究者的思维习惯完全一致，是“面向人类可读性”而非“面向内存偏移”的设计。这一特性确实让习惯0基索引的计算机专业人员感到困惑。

利：符合数学与统计学书写惯例（下标从1起），让公式到代码的翻译零摩擦，对量化、科研等领域的非计算机专业人员极度友好；与Fortran/Matlab生态一致，且逻辑索引（条件筛选）完全绕开位置数字，实际建模时感知不到偏移。

弊：与主流编程语言（C/Python/Java）的内存偏移思维（指针+0）彻底割裂，增加跨语言开发者的心智负担；边界循环中1:length(x)在空向量时错误生成c(1,0)导致隐蔽Bug，模运算（%%）需额外处理0值，违背通用工程直觉。

本质：这是“面向数学人类”而非“面向计算机硬件”的设计，利在领域直觉，弊在通用工程。工程上的解法是严格禁止裸写1:n，强制使用seq_along()和seq_len()封装修正，用纪律规避原生缺陷。

理解索引的本质，本质上是理解R的内存模型和对象设计哲学。遵循上述机制，能够让你编写的R代码在高频数据清洗和复杂模型构建中，既保持逻辑清晰，又避免因隐式降维或部分匹配导致的致命逻辑错误。

六、基础语法

1. 向量化运算

R语言最核心的设计理念之一是向量化运算：运算符和函数可以直接作用于向量的每一个元素，而无需显式编写循环。

a <- c(2, 4, 3, 1, 5, 7)


# 非向量化方式（for循环）
for (i in 1:length(a)) {
  print(a[i] * 2)
}


# 向量化方式（一行搞定）
a * 2  # [1] 4 8 6 2 10 14


# 向量化条件筛选
a[a > 2]  # [1] 4 3 5 7

向量化不仅让代码更简洁，更重要的是运行效率远高于显式循环——因为R的内部函数本身就是用C/Fortran优化过的。

2. R的循环补齐机制

循环补齐（Recycling Rule）是R向量化运算的核心实现机制之一：当两个长度不同的向量进行逐元素运算时，R会自动将短向量从头到尾重复（循环），使其长度与长向量一致，再执行运算。

2.1. 核心规则

  • 长度成整数倍：直接补齐，无提示。

    c(1, 2, 3) + c(1, 2)  # 短向量补齐为 c(1,2,1)
# 结果: 2 4 4

  • 长度不成整数倍：补齐后运算，但给出警告（非错误）。

    c(1, 2, 3, 4) + c(1, 2, 3)  # 补齐为 c(1,2,3,1)
# 结果: 2 4 6 5
# Warning message: longer object length is not a multiple of shorter object length

    关键在于：警告仅提示数学上的“不整除”，但结果仍会生成，这极易被批量处理中淹没的警告信息所忽略，造成难以追溯的数据错位。

  • 标量是特殊的向量：R中单个数值本质是长度为1的向量，因此 df$col + 1 实质是长向量与长度为1的向量循环补齐，这是最安全、最常用的形式。

2.2. 简洁高效的数据操作

  • 按组标签赋值：为数据框添加分类标签时，短因子自动循环。

    df <- data.frame(value = 1:6)
df$group <- c("A", "B")  # 补齐为 A B A B A B

  • 构造周期序列：c(1, -1) 循环补齐生成交替正负号，常用于差分或震荡模式构造。

2.3. 致命陷阱

  • 数据框按行赋值：当赋值的行数不是短向量长度的倍数时，R静默补齐并发出警告，数据错位而代码继续运行。

    df[1:4, "new_col"] <- c(100, 200)  # 补齐为 100 200 100 200（符合预期）
df[1:4, "new_col"] <- c(100, 200, 300)  # 补齐为 100 200 300 100（警告，但可能不是本意）

  • 条件筛选中的逻辑向量补齐：df[df$value > 5 & c(TRUE, FALSE), ] 中，逻辑向量循环补齐会导致交替选取行，是极其隐蔽的Bug来源。必须在逻辑运算中确保逻辑向量长度与行数一致。

  • 矩阵与数据框的行列操作：matrix(1:6, nrow = 4, ncol = 2) 会警告并循环填充，但结果可能完全偏离预期维度。

2.4. 最佳实践

在生产级代码中，永远不要依赖隐式循环补齐处理非标量运算。当需要重复某个短向量时，显式使用 rep(x, length.out = n) 声明目标长度，既消除警告，又让代码意图一目了然。

# 不推荐（隐式依赖）
df$group <- c("A", "B")


# 推荐（显式声明）
df$group <- rep(c("A", "B"), length.out = nrow(df))

3 函数

R是函数式编程语言，几乎所有操作都是函数调用。函数式编程的核心思想是将函数作为第一等对象传递。函数在其中拥有“一等公民”的地位。这意味着函数可以赋值给变量、存入列表、作为参数传递给其他函数，甚至作为函数的返回值。R的基础函数式工具如lapply、sapply、Map、Reduce等，以及tidyverse中的purrr包，都强调了这一能力（详见后文）。

定义函数：

# 基本函数定义
my_mean <- function(x) {
  sum_x <- sum(x)
  n <- length(x)
  return(sum_x / n)
}


# 使用
my_mean(c(1, 2, 3, 4, 5))  # 3

高阶函数：R中的lapply()、sapply()、mapply()等都是高阶函数——它们接受函数作为参数。

# 使用lapply对列表每个元素平方
numbers <- list(1, 2, 3, 4, 5)
squared <- lapply(numbers, function(x) x^2)
# lapply返回列表，sapply尝试简化为向量
squared_vec <- sapply(numbers, function(x) x^2)  # [1] 1 4 9 16 25

匿名函数：无需命名的函数，常用于一次性操作：

# 过滤出偶数
Filter(function(x) x %% 2 == 0, c(1, 2, 3, 4, 5))  # [1] 2 4

4. 对象和类

R支持三种主要的面向对象系统：S3、S4和R6。

S3系统：R中最简单、最常用的面向对象系统。S3的本质是“贴标签”——给任意对象赋予一个类属性，然后通过泛型函数（generic function）根据类标签分派具体方法。

# 创建S3对象：给列表贴上类标签
person <- list(name = "Alice", age = 30)
class(person) <- "Person"


# 定义S3方法
print.Person <- function(x) {
  cat("Name:", x$name, "\n")
  cat("Age:", x$age, "\n")
}


# 调用时自动分派
print(person)
# Name: Alice
# Age: 30

S3极度灵活但缺乏严格的类型检查，大多数Base R函数和CRAN包都采用S3。典型的例子是plot()函数——当你传入一个ggplot对象时，R会自动调用plot.ggplot()。

S4系统：比S3更正式、更严格，支持多重继承和类型检查。使用setClass()和setMethod()明确定义类和方法的签名。Rmetrics套件（如timeSeries）采用S4。

# 定义S4类
setClass("Person",
         slots = list(name = "character", age = "numeric"))


# 创建S4对象
person <- new("Person", name = "Bob", age = 25)

R6系统：最接近主流面向对象语言（Python、Java、C++）的实现。支持封装（public/private）、引用语义和基于对象的方法定义。

# 加载R6包
library(R6)


# 定义R6类
Person <- R6Class("Person",
  public = list(
    name = NULL,
    age = NULL,
    initialize = function(name, age) {
      self$name <- name
      self$age <- age
    },
    greet = function() {
      cat("Hello, I'm", self$name, "\n")
    }
  )
)


# 创建实例
alice <- Person$new("Alice", 30)
alice$greet()

R6适合构建复杂的量化回测框架、风险管理引擎等大型项目。R6与S3/S4的核心区别在于：S3/S4基于泛型函数（函数决定行为），R6基于封装对象（对象决定行为）。

三种面向对象系统的选择取决于项目规模与需求：

系统 适合场景 优点 缺点
S3 探索性分析、个人工具、简单统计模型 简单、灵活、低开销 无正式类定义，缺乏类型检查
S4 大型团队项目、需严格数据结构验证的系统 类型安全、形式化 语法冗长，学习曲线陡
R6 需要管理状态、复杂管道、与外部资源交互的框架 引用语义、封装、方法链式调用 偏离R函数式范式，相对较少核心使用

Hadley Wickham在《Advanced R》中认为S3最重要，其次是R6，最后是S4。但Bioconductor社区普遍采用S4。在量化领域，对于轻量的因子研究可以继续使用S3列表；对于正式的金融产品、组合模型和风险引擎，R6的封装和状态管理更为稳健。

七、tidyverse：R数据科学的现代范式

tidyverse是由Hadley Wickham领导创建的一套生态系统，包含一系列设计一致的数据操作、可视化和编程包。tidyverse的核心理念是整洁数据（tidy data）——每一列是一个变量，每一行是一个观测，每一个单元格是一个值。

安装并加载tidyverse：

install.packages("tidyverse")
library(tidyverse)

1. 核心包

ggplot2：基于图形语法的可视化系统。通过图层叠加的方式构建图表，将数据、映射、几何对象、统计变换等元素组合在一起。

ggplot(mtcars, aes(x = wt, y = mpg)) +
  geom_point(aes(color = cyl)) +
  geom_smooth(method = "lm") +
  labs(title = "车重与油耗关系")

dplyr：数据操作语法，提供一系列“动词”：

df %>%
  filter(age > 25) %>%          # 筛选行
  select(name, salary) %>%      # 选择列
  mutate(tax = salary * 0.2) %>% # 创建新列
  arrange(desc(salary)) %>%     # 排序
  summarise(mean_salary = mean(salary)) # 汇总

tidyr：数据整理，实现数据框的长宽转换、列拆分与合并等。

purrr：函数式编程工具，增强列表操作，提供map()系列函数替代lapply()。

tibble：现代化的数据框实现，比Base R的data.frame更友好（不自动转换字符为因子、更清晰的打印输出等）。

readr：高效的数据读取，提供read_csv()、read_tsv()等函数，比Base R的read.csv()更快、更智能。

2. Base R与tidyverse的平衡

tidyverse极大提升了R的易用性和代码可读性，但并不意味着要完全抛弃Base R。

合理的策略是：工具服务于解决问题。在每一种场景下选择最稳定、最合适的语法。

  • 快速探索：tidyverse的管道操作（%>%）让数据流清晰可读
  • 性能敏感：Base R的向量化运算在某些场景下更快
  • 包开发：尽量减少外部依赖，优先使用Base R
